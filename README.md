# Точный маршрут коммивояжёра

Небольшой учебный проект на Python: поиск кратчайшего замкнутого маршрута,
который посещает каждый город ровно один раз и возвращается в первый город.
Заодно репозиторий используется для практики Git и совместной работы через GitHub.

## Запуск

Нужен Python 3.10 или новее. Сторонних зависимостей нет.

```bash
python tsp.py
```

Пример результата для четырёх вершин единичного квадрата:

```text
Route: A -> B -> C -> D -> A
Distance: 4.000000
```

Для своих данных передайте путь к JSON-файлу:

```bash
python tsp.py examples/cities.json
```

Формат входных данных:

```json
[
  {"name": "A", "x": 0, "y": 0},
  {"name": "B", "x": 3, "y": 4}
]
```

Координаты декартовы, расстояния евклидовы. Названия городов должны быть
уникальными. Допускается от 1 до 10 городов.

## Алгоритм

Первый город фиксируется как начало маршрута. Программа перебирает все
перестановки остальных городов, считает длину каждого замкнутого маршрута
и выбирает минимальную. Так рассматриваются все возможные циклы, поэтому
результат оптимален с учётом точности вычислений с плавающей точкой.

Сложность по времени — `O(n · (n − 1)!)`, по памяти — `O(n²)` для матрицы
расстояний. Ограничение в 10 городов защищает от слишком долгого перебора.
Если несколько маршрутов имеют одинаковую длину, выбирается первый найденный.

## Проверка программы

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют известные оптимальные расстояния, возвращение в исходную
точку, посещение всех городов, граничные случаи, ошибочные данные и запуск CLI.

## Практика Git

Основная ветка — `main`.

1. Исходный код добавляется первым коммитом.
2. Отдельным коммитом добавляется `.gitignore` с правилом `*.bin`.
   Локальный файл `test.bin` используется для проверки: обычная команда
   `git add test.bin` должна завершиться отказом. Опцию `-f` не используйте:
   она специально обходит правила игнорирования.
3. Пустой `team.txt` добавляется отдельным коммитом
   `Add empty team file for teammate pull requests`. Это исходная точка
   для форков и последующего упражнения с отменой коммита.
4. После принятия двух пул-реквестов выполняются упражнения с новой веткой,
   `git revert`, слиянием и переносом одного коммита через `git cherry-pick`.

### Действия двух сокомандников

Каждый сокомандник выполняет эти действия в своём аккаунте GitHub:

1. Открыть основной репозиторий и нажать **Fork → Create fork**.
2. В своём форке открыть `team.txt` и нажать кнопку редактирования.
3. Написать свою настоящую фамилию отдельной строкой и завершить её переводом
   строки. Если в файле уже есть фамилии, сохранить их.
4. Нажать **Commit changes**, указать сообщение `Add my surname` и сохранить
   изменение в своём форке.
5. Нажать **Contribute → Open pull request**. Проверить, что целевой репозиторий
   — основной, целевая ветка — `main`, а исходный репозиторий — свой форк.
6. Создать пул-реквест и отправить владельцу ссылку на него.

Два изменения первоначально пустого файла могут конфликтовать при слиянии:
тогда нужно сохранить обе фамилии, каждую на своей строке.
